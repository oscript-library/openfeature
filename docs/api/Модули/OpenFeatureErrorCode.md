# Модуль `OpenFeatureErrorCode`

Коды ошибок оценки флага. Модуль даёт константы вместо строковых литералов.

Спецификация: [Error code](https://openfeature.dev/specification/types#error-code).

Ошибка оценки не приводит к исключению: клиент возвращает значение по умолчанию, а причину отказа описывают поля
`КодОшибки` и `СообщениеОбОшибке` в [`EvaluationDetails`](../Классы/EvaluationDetails.md).

## Функции

Каждая функция возвращает `Строка` и не принимает параметров.

| Функция | Значение | Когда возникает |
|---|---|---|
| `ПровайдерНеГотов()` | `PROVIDER_NOT_READY` | Значение запрошено до инициализации провайдера |
| `ФлагНеНайден()` | `FLAG_NOT_FOUND` | Флаг не найден |
| `ОшибкаРазбора()` | `PARSE_ERROR` | Ошибка разбора данных, например конфигурации флагов |
| `НесоответствиеТипа()` | `TYPE_MISMATCH` | Тип значения флага не совпал с ожидаемым |
| `ОтсутствуетКлючТаргетинга()` | `TARGETING_KEY_MISSING` | Провайдеру нужен ключ таргетинга, но он не передан |
| `НекорректныйКонтекст()` | `INVALID_CONTEXT` | Контекст оценки не удовлетворяет требованиям провайдера |
| `ФатальнаяОшибкаПровайдера()` | `PROVIDER_FATAL` | Провайдер в неустранимом состоянии ошибки |
| `Общая()` | `GENERAL` | Прочие ошибки, включая неожиданный сбой провайдера или хука |

## Применение

Разбор кода в прикладном коде:

```bsl
Детали = Клиент.ПолучитьЛогическоеСДеталями("new-checkout", Ложь);

Если Детали.КодОшибки = OpenFeatureErrorCode.ФлагНеНайден() Тогда
	Журнал.Предупреждение("Флаг не заведён в системе управления");
ИначеЕсли Детали.ЭтоОшибка() Тогда
	Журнал.Ошибка(Детали.КодОшибки + ": " + Детали.СообщениеОбОшибке);
КонецЕсли;
```

Заполнение кода в своём провайдере:

```bsl
Результат = Новый ResolutionDetails(ЗначениеПоУмолчанию);

Возврат Результат.ЗаполнитьОшибку(OpenFeatureErrorCode.ФлагНеНайден(),
	СтрШаблон("Флаг %1 не найден", Ключ), ЗначениеПоУмолчанию);
```
